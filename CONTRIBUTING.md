# Contributing

Contributions should preserve the skill's fail-closed quality model.

## Guidelines

- Keep role examples optional; never introduce a default job role.
- Preserve one-question-per-dialog interaction behavior.
- Add rules only when they are testable or auditable.
- Keep source facts, structured question data, renderers, and validators separate.
- Use synthetic examples. Do not contribute proprietary training materials or customer exams.
- Update `CHANGELOG.md` for systematic behavior changes.
- Validate Markdown structure, YAML syntax, JSON examples, links, and repository privacy before proposing changes.

## Review expectations

Changes affecting question generation should address correct-option validity, distractor plausibility, answer uniqueness, bilingual equivalence, semantic duplication, blueprint synchronization, and final-artifact verification.
